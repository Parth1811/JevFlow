## Cycle 5 (2026-09-24 07:40 UTC, D1 + E1)
- D1 done: `jevflow/supervisor.py` + `python -m jevflow run` (usage via `run -h`). Launches `claude -p <prompt> --plugin-dir <root> --output-format json [--resume sid] [--max-turns N] --permission-mode acceptEdits` in the project with its own process group; stdout/stderr kept per run in `.jevflow/runs/` (unique names, reruns never overwrite). After each exit it reloads state.json: done -> 0, needs_human -> 4 (never relaunched; deleting NEEDS_HUMAN.md and rerunning clears it, journaled `human_resolved`), time / Jev budget -> 2, restarts >= max_restarts -> 2, config errors (no flow in exactly that dir, bad flow, missing or non-executable binary, not a plugin dir) -> 3, live lease -> 5 (new code, state not touched). Restart prompt carries goal, current phase, done_when, check and the last BLOCK reason; resume uses the session_id from the JSON result, and a resumed run with no result starts fresh next time. Lease: `.jevflow/lock` with pid/host/ts plus an exclusive flock, so a lock left by a dead supervisor is taken over (journaled) and a live one is refused. Watchdog: newest of transcript mtime (from SessionStart), state.json, run output and launch time; idle >= `hang_minutes` kills the whole process group (SIGTERM, then SIGKILL) and relaunches, counted as a restart. A busy runaway child is killed at `max_total_minutes` + 60 s and ends with exit 2. StopFailure `rate_limit|overloaded|server_error` recorded after this launch -> backoff 30 s doubling to 600 s, capped by remaining time, not counted as a restart, 6 in a row -> exit 2; an older last_error is ignored. SIGTERM/Ctrl-C to the supervisor kills the child group, journals `supervisor_interrupted`, exits 130. Budget report printed (or `--json`) and written to `.jevflow/last_run.json`, plus a `supervisor_end` journal entry.
- Flow change: `limits.max_restarts` may now be 0 (run once, never relaunch); every other limit is still >= 1.
